Possibly meant _import instead of _local.

Why is this an issue?

Declaring _local inside a nested procedure when a variable of the same name already exists in the enclosing scope creates a new, separate local instead of referring to the outer one. If the outer variable was the one actually meant, the nested procedure ends up reading or writing an uninitialized shadow instead.

Code examples

Non-compliant code example

_method a.m()
  _local log_stream << !terminal!
  _proc@do_something()
    _local log_stream
    log_stream.write("hello from do_something")
  _endproc
_endmethod

Compliant solution

_method a.m()
  _local log_stream << !terminal!
  _proc@do_something()
    _import log_stream
    log_stream.write("hello from do_something")
  _endproc
_endmethod
