Variable definition hides another variable with the same name.

Why is this an issue?

A variable definition that reuses the name of a variable already visible in an enclosing scope shadows the original. Code that follows can end up reading or writing the wrong one, and the mistake is easy to miss since both variables share the same name.

Code examples

Non-compliant code example

_local x << 10
_for i _over 1.upto(10)
_loop
  _local x << 20
  show(x)
_endloop
