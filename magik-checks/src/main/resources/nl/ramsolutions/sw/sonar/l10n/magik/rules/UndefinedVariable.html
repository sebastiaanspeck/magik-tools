A prefixed variable is used without being declared in the local scope.

Why is this an issue?

By convention, an identifier prefixed with l_, i_, p_, or c_ signals that it is meant to be a local, iterator, parameter, or constant variable. When such a name is not actually declared in the local scope, Magik resolves it as a global instead, usually because a _local declaration is missing, and referring to an undeclared global is often a bug.

Code examples

Non-compliant code example

_method object.do_something()
  write(l_a)
_endmethod

Compliant solution

_method object.do_something()
  _local l_a << 10
  write(l_a)
_endmethod
